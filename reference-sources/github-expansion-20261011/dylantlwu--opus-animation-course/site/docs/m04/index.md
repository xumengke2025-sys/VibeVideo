## 1. 本课目标

- 用**视觉层级**决定每一帧「第一眼看哪、第二眼看哪」，并会用「眯眼测试」检验
- 掌握构图的几条硬规则：单一焦点、留白、安全区、对齐
- 会用转场表达意思，而不是装饰：硬切、匹配剪辑、形变、擦除各自说什么
- 建立自己的**视觉隐喻库**：把抽象概念变成可以画出来的东西
- 产出：一支片子的 4 张 style frames + `LOOK.md`

## 2. 原理

### 2.1 视觉层级：观众的眼睛只有一双

同样四条信息，三种处理：

<AnimDemo src="/demos/m04-hierarchy.html" caption="① 一样大一样色一起出现：观众不知道先看哪；② 大小 + 对比 + 一个强调色；③ 再加上「主角先动、动得最多」" :poster="3.5" />

层级的四个杠杆，**从强到弱**：

| 杠杆 | 怎么用 | 注意 |
|---|---|---|
| **运动** | 主角先动、动得最多；配角后到、动得少 | 最强的信号——同时动的东西越多，层级越乱 |
| **时间** | 先出现的先被看（这就是 reads） | 和 M3 的 reads 是同一件事 |
| **大小** | 最重要的东西大 3 倍以上 | 「稍微大一点」等于没有层级 |
| **对比 / 颜色** | 强调色只给一个东西 | 两个强调色 = 没有强调色 |

### 2.2 眯眼测试

把一帧模糊掉，看还剩下什么。还能一眼认出的，就是你的第一层级：

```bash
cd ~/ops_animation/studio
node render/render.mjs work/<片名>/index.html --still=3.5 --out=out/check/frame.png
node render/ffmpeg.mjs -i out/check/frame.png -vf "gblur=sigma=24" -update 1 out/check/squint.png
```

![眯眼测试](/img/m04-squint.png)

上图是 2.1 示例在 3.5 秒的眯眼测试：左栏糊成一片，找不到焦点；中、右栏一眼就是那个「4」。**每个镜头的关键帧都应该过这一关**——这也是你可以直接要求 Opus 做的自检。

### 2.3 构图的硬规则

| 规则 | 说明 |
|---|---|
| 单一焦点 | 每一帧只有一个「第一眼」。两个焦点会互相抢 |
| 留白 | 留白不是浪费，是给焦点的「呼吸空间」。科普片常见错误是填满 |
| 安全区 | 横屏四周留 5%；**竖屏上 150px、下 170px、左右 60px**（避开平台 UI） |
| 对齐 | 元素要么对齐网格 / 彼此对齐，要么明显不对齐（故意的张力）。「差一点对齐」最难看 |
| 文字尺寸 | 1080p 下正文 ≥ 28px，字幕 ≥ 36px（手机上看） |
| 三分法 | 主体放在三分线交点附近，比居中更有方向感；但瑞士风等风格可以违反——风格优先 |

### 2.4 转场语法：每种转场都在「说话」

同样两个镜头（A：信号，B：手机），四种转场：

<AnimDemo src="/demos/m04-transitions.html" caption="转场点都在 2.0 秒。用 0.25× 看匹配剪辑和形变的区别" :poster="2.1" />

| 转场 | 它在说什么 | 适合 |
|---|---|---|
| **硬切** | 「下一件事」 | 默认选择；切在节拍或句尾 |
| **匹配剪辑** | 「这两件事有关系」 | A 结尾的位置 / 形状 = B 开头的位置 / 形状 |
| **形变** | 「这个**变成了**那个」 | 因果、演化、同一事物的两种状态 |
| **擦除** | 「翻页 / 进入下一步」 | 步骤、对比（擦除方向 = 阅读方向） |
| 叠化 | 「时间流逝」或「我不知道怎么转」 | 慎用：最容易显得廉价 |

**选择规则**：转场的含义要和旁白的逻辑一致。旁白说「所以」，用形变或匹配剪辑；旁白说「另一方面」，用擦除或硬切。

### 2.5 视觉隐喻库

科普片的核心手艺：把抽象概念变成**可以画的东西**。

| 概念 | 视觉隐喻 |
|---|---|
| 距离 / 范围 | 圆、球面、等高线 |
| 时间延迟 | 在路上飞的点、拉长的线 |
| 不确定性 | 模糊的一团、胀缩的边界、多个半透明副本 |
| 比较 | 并排的柱子、同一把尺子 |
| 因果 | 一个元素推动 / 变成另一个 |
| 规模 | 嵌套（俄罗斯套娃）、缩放镜头 |
| 流程 | 沿路径移动的点、管道 |
| 选择 / 排除 | 打叉、变暗、被推出画面 |
| 层级 / 结构 | 树、嵌套框、缩进 |
| 增长 | 生长的线、堆叠的块 |

M7 示例片几乎每个镜头都在用这张表：距离 → 球面，误差 → 胀缩 + 模糊一团，排除 → 打叉。

### 2.6 设计 token

视觉语言最终要落到一份 token，所有镜头共用（详见[风格专题 · 使用方法](/style/workflow)）：

```js
const C = { bg: '#1C1C1C', ink: '#ECECEC', accent: '#FFD54A', error: '#FC6255' };
const TYPE = { h1: 72, h2: 48, body: 36, caption: 28 };   // 字号阶梯：每级约 1.4 倍
const GRID = { margin: 96, col: 12 };
```

## 3. 拆爆款

回到 [UI 形变循环](https://x.com/twoclipping/status/2103273003555402193)：它的视觉层级几乎全靠**运动**完成——画面里永远只有一个元素在变，眼睛不需要找。再看[西方文明史](https://x.com/IterIntellectus/status/2103212539895017864)：2 分钟里每个镜头都只有一个焦点，配色在全片里有一个从冷到暖的演变（World 一栏的「颜色随剧情变化」）。

## 4. Opus 实操：先出 style frames

M3 的脚本已经写好了。在动画之前，先锁定视觉：

```text
读 CLAUDE.md。work/<片名>/script.md 是已批准的脚本。
先不做动画。为节拍表里的第 1、3、5、7 拍各出一张静帧（style frames），要求：
- 每张只有一个视觉焦点，在 --still 输出后跑眯眼测试（gblur sigma=24），附上模糊图
- 每张写一行：用了视觉隐喻库里的哪个隐喻
- 共用一份 token（颜色 ≤ 4、字号阶梯、网格），写在 index.html 顶部
做完停下，我审完再写 LOOK.md。
```

审 style frames 时只问三个问题：
1. 眯眼之后，第一眼是不是这一拍最想让观众看到的东西？
2. 四张放在一起，像不像同一支片子？
3. 有没有违反 CLAUDE.md 第 4 节的「反 AI 味」清单？

## 5. 导演训练

1. **眯眼测试 ×10**：从[拆片库](/cases)的片子里截 10 帧，模糊后写下第一眼看到什么，再看原图对不对
2. **转场翻译**：把 M3 脚本里所有的「所以」「但是」「另外」找出来，给每一处配一个转场并写理由
3. **隐喻扩充**：给你自己的领域补 5 条视觉隐喻，加进上面的表
