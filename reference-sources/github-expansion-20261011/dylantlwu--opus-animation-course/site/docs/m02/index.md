# M2 · 拆片与复刻

<div class="lesson-meta"><span class="tech">技术：提示词解剖、节拍网格</span><span class="dir">导演：拉片</span><span>约 6 小时</span></div>

## 1. 本课目标

- 能把一支爆款拆成一张**拉片表**（镜头 / 时间 / 事件 / 运动 / 转场 / 节拍）
- 理解好简报（brief）的六个部件，能写出 Opus 不会误解的简报
- 理解「剪在拍上」：用 BPM 网格安排所有时间
- 复刻一支 15 秒短片，并和原片逐镜对比

## 2. 原理

### 2.1 为什么「一句话出片」大家做出来都一样

那条 220 万播放的 showreel 提示词，核心只有一句：让 Opus 做 15 秒动效视频，证明自己是出色的动效设计师，「like it's your showreel for a résumé」。

它好用的原因：给了**角色**（动效设计师）、**标准**（简历作品集级别）、**授权**（go all out）。
它的问题也在这里：没有内容、没有受众、没有风格约束——于是几百人拿到的是同一个「Opus 默认审美」。社区管这叫 **brief contagion**。

**一句话提示词是在让 Opus 当导演；本课要你自己当导演。**

### 2.2 简报的六个部件

| 部件 | 写什么 | 坏例子 → 好例子 |
|---|---|---|
| ① 目的与受众 | 谁看、看完能怎样 | 「做个酷炫视频」→「让没学过物理的高中生理解 GPS 为什么要 4 颗卫星」 |
| ② 硬约束 | 时长、画幅、fps、色板、字体、禁区 | 「短一点」→「15s，1920×1080，30fps，最多 3 种颜色，禁止渐变背景」 |
| ③ 结构 | 镜头数、每段时长、节拍 | 「节奏快」→「120 BPM，4 小节，每小节一个镜头，剪辑点在小节线」 |
| ④ 影视语言 | 用术语描述运动和转场 | 「转场酷一点」→「镜头 2→3 用匹配剪辑：方块形变成下一镜的字母 O」 |
| ⑤ 参考 | 具体的片子、截图、网站 | 「苹果风」→「参考 apple.com/airpods 首屏：大留白、单一主体、慢推」 |
| ⑥ 流程指令 | 闸门、交付物 | （不写）→「先给 G1 分镜，等我批准」 |

社区里效果最好的简报，都在 ②③④⑤ 上花了最多字数。

### 2.3 剪在拍上

<AnimDemo src="/demos/m02-beats.html" caption="120 BPM：1 拍 0.5s，1 小节 2s。四个镜头的剪辑点（▼）都落在小节线上；镜头内的动作落在拍点上" :poster="4.6" />

把所有时间从 BPM 推导出来，而不是写死秒数：

```js
const BPM = 120, BEAT = 60 / BPM, BAR = BEAT * 4;
const pulse = (t) => Math.exp(-8 * ((t % BEAT) / BEAT));   // 每拍一次的冲击：拍点=1，然后衰减
SHOTS = [{ start: 0 * BAR, ... }, { start: 1 * BAR, ... }, ...];
```

好处：
- 换配乐时只改 `BPM`，所有镜头自动对齐
- 向 Opus 描述时说「第 3 小节第 2 拍」而不是「4.5 秒」，它不会算错
- 有人拆那条 showreel：15 秒里 7 个剪辑点，**全部**落在 128 BPM 的小节线上——观众说不出为什么，但会觉得「爽」

## 3. 拆爆款：拉片表

拉片（shot-by-shot breakdown）是影视学生的基本功：逐镜头记录发生了什么。格式：

| 镜头 | 起止 | 画面 | 事件 | 运动 / 缓动 | 转场（入） | 节拍 |
|---|---|---|---|---|---|---|
| 1 | 0.0–2.0 | 红色圆形居中 | 随每拍脉动 | 放大 outExpo + 每拍冲击 | 硬切（开场） | 第 1 小节 |
| 2 | 2.0–4.0 | 黄色方块 ×4 | 每拍滑入一个 | outBack，左侧 120px 滑入 | 硬切 | 第 2 小节 |
| … | | | | | | |

↑ 这就是上面示例的拉片表前两行。注意「事件」一列：**每个镜头都必须有事件**——「方块停在那里」不算镜头。

去 [爆款拆片库](/cases) 挑一支 15 秒以内的片子，用这个表格把它完整拆出来。

## 4. Opus 实操：从拉片表到复刻

### 4.1 把拉片表变成简报

```text
读 CLAUDE.md。我要复刻一支参考片的「结构和节奏」，但换成我自己的内容。
参考片拉片表见 exercises/m02/breakdown.md。

① 目的与受众：[你的内容，比如「介绍我的开源项目 XXX」]，给 [受众] 看
② 硬约束：15s，1920×1080，30fps；色板 [3 个色值]；字体 PingFang SC；禁止渐变背景、禁止所有元素同时淡入
③ 结构：沿用参考片的镜头数和剪辑点；[BPM] BPM，剪辑点全部落在小节线上
④ 影视语言：[拉片表里你最想保留的 2–3 个运动/转场，用术语写]
⑤ 参考：拉片表 + [截图路径]
⑥ 流程：先给 G1 分镜（每个镜头标注对应参考片的哪个镜头），等我批准
```

### 4.2 对比审片

成片出来后，用 `--sheet` 在参考片的同一批时间点上截图，和参考片截图并排对比：

```bash
node render/render.mjs work/m02/index.html --sheet=0.5,2.5,4.5,6.5,8.5,10.5,12.5,14.5 --cols=4 --out=out/check/m02.png
```

逐镜回答：节奏对上了吗？哪个镜头的「事件」比原片弱？

::: warning 常见翻车
- **Opus 把复刻做成了「同风格新片」**：在简报里强调「沿用参考片的镜头数和剪辑点」，并让它在分镜里逐镜标注对应关系
- **时间算错**：用「第几小节第几拍」描述，让它在代码里用 BEAT / BAR 常量
- **一次改太多**：每轮只提 1–2 个具体问题（M5 会系统讲）
:::

## 5. 导演训练：拉片 ×3

用拉片表完整拆 3 支片子：

1. 一支 Opus 爆款（从拆片库挑）
2. 一支专业动效作品（比如苹果发布会的产品片段，或 B 站动效区的作品）
3. 一支你喜欢的科普视频的前 30 秒

拆完回答：**专业作品和 Opus 爆款最大的差别在哪一列？**（多数人的答案是「事件」和「节拍」）
