# M5 · 导演工作流

<div class="lesson-meta"><span class="dir">导演：闸门、审片、反馈纪律</span><span class="tech">技术：--sheet / --strip / --verify、新会话严审、HANDOFF</span><span>约 6 小时</span></div>

## 1. 本课目标

- 把社区共识流水线落成自己的闸门 G0–G4，并且**稳定执行**
- 熟练使用四件审片工具，知道每件工具抓哪一类问题
- 建立**反馈纪律**：每轮最多 2 条，格式「镜头 + 时间 + 问题 + 期望」
- 会用「新会话严审」和 `HANDOFF.md` 管理长片
- 产出：你自己的 `CLAUDE.md` v2

## 2. 原理

### 2.1 为什么要闸门

一句话出片的问题不是「做不好」，而是**做坏了你不知道坏在哪一步**。闸门把一次大赌博拆成五次小确认，每次只确认一件事：

| 闸门 | 只确认这件事 | 在这里改的成本 |
|---|---|---|
| G0 简报 | 我们要做的是同一支片子吗？ | 一句话 |
| G1 分镜 | 讲的顺序对吗？reads 对吗？ | 改一行文字 |
| G2 静帧 | 长得对吗？（风格、层级、构图） | 改一个 draw 函数 |
| G3 预览 | 动得对吗？（节奏、转场、跳帧） | 改时间参数 |
| G4 终版 | 技术规格对吗？ | 重渲一次 |

越往后发现问题越贵：G1 发现「顺序不对」改一行字；G4 才发现，要改分镜、重做镜头、重渲整片。

### 2.2 四件审片工具，各抓各的

| 工具 | 抓什么 | 抓不到什么 |
|---|---|---|
| `--sheet=t1,t2,…` | 构图、层级、风格一致性（静态问题） | 运动和节奏 |
| `--strip=a:b --n=N` | 转场处的**单帧跳变**、闪烁 | 全片节奏 |
| `--verify` | 藏起来的计时器、帧间状态、随机数 | 「能复现的错误」——画错了但每次都错得一样 |
| `--clip --scale=0.5` | 节奏、整体观感 | 单帧问题（全速看不出来） |

单帧跳变的例子——下面这个镜头 A 的结束条件少写了 0.04 秒，全速播放几乎看不到：

::: tip 抽查不等于全检
`--verify` 和 `--sheet` 都是**抽查**。M7 示例片制作时就遇到过：闪电刚出现的 0.3 秒里，声波半径是负数，canvas 报错——抽查的时间点都没碰到这几帧，只有整片渲染才跑到。所以 G4 的整片渲染本身也是一道检查：渲染器遇到页面报错会**立刻停止、删掉不完整的文件、报出出错的时间点**，不会留下一个「看起来正常」的半成品。
:::

### 2.3 反馈纪律

**格式**：镜头 + 时间 + 问题（现象）+ 期望（具体到数值）。

**每轮最多 2 条**。为什么？
- 一次给 10 条，模型会顾此失彼，而且会「顺手」改你没提的地方
- 2 条改完再看，常常发现其他 8 条已经不是问题了（它们是同一个根因的症状）

**只改我点名的**：在 `CLAUDE.md` 里已经写了「只改我点名的镜头和问题，不顺手改别处」。每次提意见时再重复一遍也不嫌多。

**同一类问题出现第二次 → 写成规则**。这是 `CLAUDE.md` 第 6 节存在的意义。

审片记录模板：`studio/templates/REVIEW.md`。

### 2.4 新会话严审

同一个会话里，模型已经「知道」自己想做什么，会对自己的作品手软——它看到的是意图，不是结果。社区通行做法：**开一个全新的会话，只给它成品和规范，让它当甲方**。

```bash
cd ~/ops_animation/studio
claude --model claude-opus-5-5 --effort high
```

```text
你是一个挑剔的甲方，没参与过这支片子的制作。
只看这三样：work/<片名>/STORYBOARD.md、work/<片名>/LOOK.md、out/check/sheet.png。
逐镜头列问题：违反 LOOK.md 的哪一条？reads 有没有重叠？眯眼测试第一眼看到什么？
只列问题、按严重程度排序、每条给出证据（哪一张图、哪个位置）。打分 1–10。
```

然后把这份意见**筛选成 2 条**，带回制作会话。

### 2.5 长片：会话会「忘」

长片的上下文会越来越长，后半段质量下降是常态。对策：
- **分章节**：每章一个 `chapters/xx.js`，主文件只负责拼接
- **HANDOFF.md**：每次换会话前，让 Opus 更新交接文件（模板：`studio/templates/HANDOFF.md`）；新会话第一句话就是「读 HANDOFF.md」
- **分工**：社区有人把一支片子拆给 4 个 subagent——拆参考、写分镜、做镜头、审片。分工的前提是**所有人共用同一份 LOOK.md 和 timeline.json**

### 2.6 CLAUDE.md 的演化

v1（本课程给你的）是通用规则。到 M5，你应该已经积累了 5–10 条自己的规则。把它们整理成 v2：
- 删掉从来没触发过的规则（规则太多，遵守率会下降）
- 合并说的是同一件事的规则
- 每条都保留「为什么」——没有理由的规则，模型会在「合理的例外」里绕过去

## 3. 拆爆款：「90% 是 harness」

0xMovez 那篇 138 万播放的长文（[链接](https://x.com/0xMovez/status/2104216919033192746)）核心观点是：提示词只占 10%，剩下 90% 是工作台——渲染引擎、规则文件、审片循环、技能包。本课到这里，你的工作台已经有了：`render.mjs`（四件审片工具）、`CLAUDE.md`（规则）、`LOOK.md`（风格）、`REVIEW.md` / `HANDOFF.md`（流程）。

## 4. Opus 实操：完整走一遍 G0–G4

拿 M4 的 style frames 继续，这次严格按闸门做，每过一个闸门填一份 `REVIEW.md`：

```text
读 CLAUDE.md、work/<片名>/LOOK.md、work/<片名>/STORYBOARD.md。
G2 已批准。现在做 G3：把全部镜头做成动画。
做完：跑 --verify；出 --clip --scale=0.5 预览；对每个转场点前后 0.15 秒跑 --strip --n=5，
把所有 strip 图列给我，并告诉你看到的单帧问题。然后停下。
```

## 5. 导演训练

1. **找根因**：把你目前所有的审片意见列出来，按根因分组。通常 20 条意见只有 4–5 个根因
2. **两条原则**：下一支片子，每轮严格只提 2 条，记录总共用了几轮。和之前比
3. **严审对照**：同一份成品，分别在制作会话和新会话里让 Opus 自审，比较两份意见的差别
