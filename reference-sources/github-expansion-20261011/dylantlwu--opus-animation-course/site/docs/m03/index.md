# M3 · 编剧 I：科普叙事

<div class="lesson-meta"><span class="write">编剧：钩子、ABT、概念依赖图、reads、旁白</span><span class="dir">导演：信息顺序</span><span>约 6 小时 · 本课不写代码</span></div>

## 1. 本课目标

- 掌握科普短片的五段结构，能写出 3 秒钩子
- 用 **ABT** 写出一句话 logline
- 用**概念依赖图**决定「先讲什么、后讲什么」——这是科普片的逻辑骨架
- 理解 **reads**：同一时刻只给观众一个新信息
- 写出一份 60 秒、可直接送进 TTS 的中文解说稿

## 2. 原理

### 2.1 科普短片的五段结构

| 段落 | 占比（60s 片） | 任务 | 例：GPS 为什么要 4 颗卫星 |
|---|---|---|---|
| ① 钩子 | 0–3s | 制造一个「咦？」 | 「你手机里的 GPS，其实不知道现在几点。」 |
| ② 问题 | 3–10s | 把好奇心收束成一个明确的问题 | 「那它是怎么知道你在哪的？为什么偏偏要 4 颗卫星？」 |
| ③ 直觉 | 10–30s | 用观众已有的经验搭桥 | 打雷：看到闪电后数秒数，就知道雷有多远 → 一颗卫星 = 一个距离 = 一个球面 |
| ④ 机制 | 30–50s | 讲清楚真正的原理 | 3 个球面交于一点，但手机时钟不准 → 时间也是未知数 → 4 个未知数需要 4 个方程 |
| ⑤ 回报 | 50–60s | 回扣钩子，给一个「原来如此」 | 「所以 GPS 不只告诉你在哪，它还顺便帮你的手机对了表。」 |

注意 ⑤ 回扣了 ① ——这就是分镜里「Motif 要在结尾回收」在叙事层面的对应。

### 2.2 ABT：一句话 logline

把整支片子压成一句「And, But, Therefore」：

> 手机靠测量到卫星的距离来定位，**而且**三个距离就能确定一个点，**但是**手机的时钟不够准、距离全都算歪了，**所以**需要第四颗卫星把「时间」也解出来。

写不出 ABT，说明你还没想清楚这支片子在讲什么。**先改 logline，不要急着做画面。**

### 2.3 概念依赖图：逻辑训练的核心

科普片失败最常见的原因是**知识诅咒**：你已经懂了，所以意识不到观众缺了哪一步。

解法：把所有概念画成一张依赖图，**A → B 表示「理解 B 之前必须先理解 A」**：

```
光速很快但有限 ──┐
                 ├──▶ 时间差 = 距离 ──▶ 一颗卫星 = 一个球面 ──▶ 三个球面交于一点 ──┐
卫星知道自己在哪 ─┘                                                              ├──▶ 需要第 4 颗
                                    手机时钟不准 ──▶ 所有距离都差同一个量 ──────────┘
```

然后：
1. **按拓扑顺序讲**：箭头指向的概念，永远在箭头起点之后出现
2. **每个节点问一句**：目标观众已经知道它吗？不知道 → 必须有一个镜头讲它；知道 → 一句话带过
3. **砍节点**：60 秒能讲清 4–6 个节点。多了就删分支，或者拆成两集

这张图同时就是你的**分镜骨架**：一个节点 ≈ 一到两个镜头。

### 2.4 reads：一次只给一个新信息

画面上的信息顺序，就是叙事顺序在视觉上的体现。左右对比：

<AnimDemo src="/demos/m03-reads.html" caption="同样的内容。左：一次全给，观众不知道先看哪；右：按 reads 依次给，每次只有一个新信息" :poster="2.0" />

规则（已写进 `CLAUDE.md` 第 2 节）：
- **reads 不得重叠**：上一个信息被看懂之前，不出下一个
- **每个 read 留足时间**：「找到 + 看懂 + 停顿」。经验值：一个短词 ≥ 0.6s，一行字 ≥ 1.2s，一张图 ≥ 1.5s
- 结论出现后要**停**：右边的「④ 答案 + 停顿」占了 2 秒多

### 2.5 写给 TTS 的解说稿

旁白最终要交给 TTS 朗读，写法和文章不同：

| 规则 | 坏例子 → 好例子 |
|---|---|
| 短句，一句一个意思，≤ 20 字 | 「由于卫星所搭载的原子钟精度极高而手机时钟精度较低因此…」→「卫星上是原子钟，非常准。你的手机不是。」 |
| 口语，能读出来 | 「GPS 系统」→「GPS」；「即」→「也就是」 |
| 数字写成读法 | 「3×10⁸ m/s」→「每秒三十万公里」 |
| 画面替你说的，旁白就别说 | 画面在画球面时，旁白不必再说「如图所示」 |
| 每句话对应一个画面事件 | 解说稿的每一行，就是分镜的一个 read |

### 2.6 事实核查

社区吐槽最多的问题之一：**编造的数字**。规则：
- 每个数字、日期、引用，在脚本里用 `[来源: URL]` 标注
- 让 Opus 帮你找来源，但**你自己打开链接确认**
- 找不到来源的数字：改成定性描述，或者删掉

## 3. 拆爆款：GPS 讲解与「花哨幻灯片」批评

[GPS 讲解](https://www.youtube.com/watch?v=K-pgPNFcAj4) 是 Opus 5.5 科普片的代表作之一。值得看的是它**怎么用画面替代旁白**：距离 → 圆、交点 → 定位，几乎每个概念都有一个几何对应物。

同时也要看 [Hacker News 上的批评](https://news.ycombinator.com/item?id=49836374)：有人说这类片子「只是花哨的幻灯片」，节奏太快，外行跟不上。

这两点其实是一回事：**画面做得好不等于讲得明白**。节奏太快，往往是概念依赖图里漏了节点、或者 reads 给的时间不够——是编剧问题，不是动画问题。

## 4. Opus 实操：让它当编剧助理，不是编剧

Opus 写的科普稿通常「正确但平庸」。更好的分工：**你做决策，它做苦力和挑刺**。

### 4.1 选题后，让它列「误解」

```text
我要做一支 60 秒科普：[题目]。目标观众：[比如「没学过大学物理的高中生」]。
1. 列出这个题目最常见的 5 个误解，每个说明为什么人们会这么想
2. 列出理解这个题目所需的所有概念，标出哪些是目标观众大概率不知道的
不要写脚本。
```

### 4.2 你画依赖图，让它挑刺

```text
这是我的概念依赖图（附上）。请检查：
1. 有没有漏掉的前置概念（知识诅咒）
2. 有没有箭头方向错了
3. 60 秒内哪些节点该砍
```

### 4.3 你写稿，让它扮演观众

```text
你是一个 14 岁、没学过这个题目的中学生。逐句读这份解说稿，
在每一句后面标出：✅ 听懂了 / ❓ 有点懵（说明哪里懵）/ 😴 无聊了。
不要给修改建议，只报告感受。
```

最后一步建议**开一个新会话**——同一个会话里它已经「知道答案」，扮演不好外行。

## 5. 编剧训练

1. **ABT 练习**：给下面 3 个题目各写一句 ABT logline：
   - 为什么天空是蓝的
   - 为什么飞机能飞
   - 大模型为什么会「幻觉」
2. **依赖图练习**：挑其中一个，画出完整的概念依赖图（纸笔或 Mermaid 都行），然后砍到 6 个节点以内
3. **钩子练习**：为同一个题目写 5 个不同的 3 秒钩子（反常识 / 提问 / 数字 / 场景 / 悬念各一个），挑最好的一个，写下为什么
