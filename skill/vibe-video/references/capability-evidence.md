# 能力登记与证据边界

一项能力的记录包含：明确动作、适用条件、来源/原创状态、源码版本与输入、实际输出哈希、观察证据与限制。以下字段分别填写，不能用一个总分替代：

| 字段 | 什么才算完成 |
|---|---|
| `rendered` | 存在实际媒体且完整解码通过 |
| `stills_reviewed` | 实际查看代表画面，并记录具体发现 |
| `sequence_reviewed` | 实际查看动作建立/中间态/结果及风险窗口 |
| `realtime_played` | 按正常速度播放并观察；接触表不算 |
| `audio_listened` | 实际听了对应版本声音；音量分析不算 |
| `variant_rebuilt` | 更改内容后重新构建，检查事实和动作保持正确 |
| `seek_checked` | 写清同页、新页面、新进程及状态/像素测试范围 |

示例注册表在 `assets/style-studio/capabilities.json`。输出和完整审片保留在制作项目，注册表摘要链接到项目证据。移动文件或重新混音后，核对输出哈希；源文件修改后旧审片只说明旧版本。

添加能力前先寻找可运行入口和实际输出。没有许可的工程不复制代码；只有技术宣传或提示词不能登记为源码已验证。第三方素材单独记 CREDITS。文档研究、原作观看、原作重建、原创验证分别记录。

更改内容后，优先复验被更改的对象、文字、数据、时间和边界；没有变更或新疑点时，不重复整套检查。脚本只会产生机器证据，主 Agent 的观察记录必须来自实际看过/听过的输出。
