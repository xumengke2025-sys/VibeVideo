# 从公开 Opus 动画流程吸收的制作检查

用于新建完整影片、旧片质量下降或用户要求提升完成度。先读本页，再按具体缺陷进入导演、美术和独立审片文档。本页加强执行节点，不替换既有引擎，不要求安装上游技能。

制作要求由主 Agent 执行，先落实 SKILL.md 的两种交付模式。内部样段不常规调用导演或审片子代理；下述独立审片方法仅用于用户选择的待交付版本审核，不强制 `user_feedback` 执行。

项目或用户偏好效果图先行时，先按 [concept-first.md](concept-first.md) 确定整体视觉、动作空间和镜头通道，复用已有认可方案，再进入下述关键样段。概念图不能代替实际动作、连续摄影与声音的验证。

## 1. 先说明观众何时看懂

在现有镜头表增加简短 `reads`（理解顺序）：观众先认出什么、再看到什么改变、最后理解什么结果；每项写出现时刻、最早可辨认时刻和离开时刻。低成本单镜可直接写一句，不新建重复计划。

动作完成时间不等于理解完成时间。文字动画结束后才开始计算完整阅读停留；相机移动、字幕、关键动作同时抢注意时，错开它们，而不是整体加速。旁白主导时按实际录音与重音，音乐主导时按实测拍点；不要把产品片“每秒新刺激”当作科学解释的通用标准。

例如止回阀：先看清阀瓣与阀座接触 → 压差变化、阀瓣离座和弹簧压缩 → 看清打开后的流路。接触处先让结构可辨，再开始运动；流动标注不能盖住阀瓣。正确性与学习顺序优先于炫技。

## 2. 完成一个关键片段，再扩展整片

已有简化预演用于验证因果和空间；在批量精修前，再选本片最难的完整动作与相邻转场，制作一段接近最终品质的样段。通常 3–8 秒即可，但长度服从完整的建立、变化和结果，不裁掉必要阅读时间。简单短片可直接用整片，避免额外流程。

样段使用实际输出路线、最终画幅、正式字体/素材/材质和关键声音，制作角色按需要检查手机观看尺寸与原尺寸。包含本片最容易失败的内容：机械接触、角色手持物、细文字、快速摄影或复杂转场。制作中发现严重缺陷及时处理，不为样段额外派独立审片。设定图或低清白模不能证明正式材质、文字与运动质量成立；选择 AI 审核时，样段观察不能代替待交付版本的完整审核覆盖。

样段记录可直接并入 production brief：输出路径、范围、实际质量设置、已证明的做法、尚未解决的限制。AI 审核最多一次修复并必要局部复核，达到预算即展示当前版本和问题，不靠不断新建样段重置计数。

## 3. 把空间关系变成可检查的数据

对文字、关键零件、面部、手持物、字幕区等登记稳定 ID、屏幕包围框或投影区域，以及明确允许的重叠关系。文字/标注由同一世界→屏幕变换得到；角色手持物跟手部锚点，机械零件跟同一行程状态。避免给相机、主体和标注各手填一套坐标。

已有布局检测器就复用；没有时在任务工程加入最小检查，或明确手动检查范围，不为一次视频搬入整套上游框架。检查越界、文字互压、遮住关键动作和中文缺字；转场、快速位移与极端姿态加密。像素阈值要随最终分辨率调整。自动框相交只能发现候选问题，不能判断故意遮挡是否合理；没有登记的对象和没有检查的帧不在其覆盖范围内。

本技能目前没有通用自动布局检测器；不能把下面上游脚本的存在写成已在本项目执行。既有 shot_contract/帧差脚本也不做这些布局判断。

## 4. 独立审片先看表达，再查符合性

审片分两个观察层次，使用同一批媒体证据：

- **首次观看理解**：先只给受众、题材、画幅和成片，不提前给剧情解释或制作方自评。审片者写“我看到了什么变化、哪里没看懂、注意力落在哪里”，检查画面能否自明。正常速度观看或听音做不到时记录限制，不假装成首次观看体验。
- **符合性与细节**：再读 brief、镜头表、`reads`、事实来源和事件表，逐帧与完整音轨核对计划、知识、阅读停留、接触、布局和声音。计划写得正确不代表画面传达成功；故意的省略也不能仅因偏离计划而判错。

逐帧审核与整体观看承担不同任务：逐帧发现闪帧、穿透、错字等；整体观看发现节奏单调、重复说明、看不懂或声音遮盖。机器帧差、运动比例、静音比例不决定观感通过，不用无意义的运动来过指标。

## 5. 修复要保住已经有效的部分

每轮修复写一句预期：“改动 X，应改善 Y，同时保留 Z”。把用户明确喜欢的镜头、已核验事实与关键动作作为保护项。优先局部修改，不因一个穿透问题重写全部运镜或替换全片画风。

复核时比较同一动作前后的完整窗口：缺陷是否消失，主体是否变小、节奏是否变慢、可读停留是否减少、声音是否被盖住。把新退化登记为缺陷，不能只关闭旧 ID。纯音频改动优先重新混音/封装；视觉流确实等同时可按独立审核的映射规则复用视觉证据，但必须检查新混音和音画关系。

若上一版某方面更好，在事实与用户约束允许的前提下保留或恢复那部分；“修复更多”不自动等于“整体更好”。AI 审核的一次修复上限与最终版本哈希规则继续适用；用户反馈修改不强制启动另一轮独立审片。
