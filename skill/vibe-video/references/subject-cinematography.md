# 让摄影机伴随主体行动

适用：运动主体、空间旅行、因果传播、要求灵动或复杂运镜的作品，以及固定中心展示过多的旧片。这里的“看向”是相机朝向/叙事关注对象；光学对焦距离、景深和拉焦是另一个控制通道，不把 lookAt 变化称为拉焦。

## 改变默认决策

先问“谁在去哪里、为什么跟着它走、途中发现什么”。设计能被理解的世界路径，再选择伴随距离、机位和看向点。主角可以是人物、鸟、零件、流体示意粒子或光的传播前沿；不是所有题材都要编造旅行。运动主体的默认候选是跟拍；接触、比较或阅读阶段可以有目的地停机。

跟拍的核心是三个时间函数：主体 `S(t)`；相机 `C(t)`；关注对象 `T(t)`。让相机位置和看向点分别随主体/事件变化，而不是 `C(t)` 绕固定 `T=[0,0,0]`。主体可以稳定留在画面一侧；背景掠过、透视变化、遮挡和前后景速差证明它正在穿过空间。Canvas 主体与背景同量平移会抵消运动，单张图缩放也不提供真实三维视差。

不要把全部元素锁死到相机：环境保留世界坐标；必要 HUD 固定屏幕；世界标注每帧由最终几何位置投影。主体有 shader 位移时也要纳入锚点。大字卡和字幕不应挤掉转弯后的行进空间。

## 可按内容组合的摄影手段

|任务|主体 / 相机 / 注意关系|最易失败的地方|
|---|---|---|
|一路陪伴|侧后方或并行跟拍，保持身份，视线略提前；起步与转弯改变距离/响应|目标始终在原点；相机和整个背景绑在一起；急转角时偏移翻转|
|带观众入场|低位穿行，前景短暂掠过，主体重新出现|只有远背景；主体长期被挡；路径穿模|
|先看行动再看后果|伴随→减速→拉开/升高；看向点由主体交给环境结果|相机提前放弃主体；揭示太快；中间无人可看|
|连续注意接棒|从 A 的动作/接触沿因果路径移向 B；旧锚点退出前建立新锚点|任意换目标；转向过猛；只用闪光覆盖跳变|
|改变空间感|机位距离与 FOV 联动，近距离广角强调掠过，远距离窄 FOV 压缩层次|只缩 FOV 当成移动；滥用 dolly zoom；竖屏把侧移主体裁掉|
|精读关键动作|动中减速、停留接触，再重新跟随|全片停机；无原因的漂移；为了炫技让机制读不懂|

不要求每片做齐。以题材选一个主摄影动作和有意义的变化，保持运动与安静的节奏。复杂镜头可以很慢；手持噪声、roll、speed ramp、景深和重击音只在有动机且真实验证时加入。

## 可直接迁移的实现

`assets/subject-camera.mjs` 为原创无引擎依赖工具；`follow2D` 返回世界相机中心，`follow3D` 返回数组姿态。复制单文件到项目，用本项目引擎应用姿态；它不改变原 cinematic-starter 的依赖和复制方式。

```js
import {Vector3} from 'three';
import {follow3D} from './subject-camera.mjs';
// 用本片主体的实际绝对时间路径；主体绘制也调用同一函数。
const subjectAt = t => [3*Math.sin(t*.55), 1.2, t*3];
const cameraAt = follow3D({
  subject: subjectAt, range: [0, 12],
  offset: [3.2, 1.6, 6], space: 'heading',
  response: .10, history: .6, samples: 24,
  lag: .04, lead: .12, fov: 42,
});
function renderAt(t) {
  subject.position.fromArray(subjectAt(t));
  const pose = cameraAt(t);
  camera.position.fromArray(pose.position);
  camera.up.set(0, 1, 0);
  camera.lookAt(new Vector3(...pose.target));
  if (pose.roll) camera.rotateZ(pose.roll * Math.PI / 180);
  camera.fov = pose.fov;
  camera.updateProjectionMatrix();
  camera.updateMatrixWorld(true);
  renderer.render(scene, camera);
}
```

数值仅是世界单位和秒的起点，按主体尺寸、速度和画幅改。`offset=[right,up,back]`；heading 根据平滑水平速度决定，up 使用世界上方向。`space:'world'` 时 offset 是固定 XYZ 向量，适合竖直传播、往复零件或不希望相机绕转的场景。急停、垂直飞行和方向反转不自动产生连续朝向；改用世界偏移、专门设计的朝向轨迹，或预计算平滑运输标架，不用强加摇摆掩盖跳变。

`response` 是秒制尾随指数卷积，`lag` 是位置延迟，`lead` 是速度前瞻；卷积在有限历史内归一化，每个 t 重新采样，不依赖上一个渲染帧。主体采样器本身也须可寻址；有物理历史则先缓存。history 太短、sample 太少会影响平滑质量；没有避障、自动主体屏幕占比求解、景深或真实快门。不要把这个工具称为自动电影导演。

跟拍转揭示可用 `blendPose(follow(t), reveal(t), smoother(progress))`；它混合 position/target/FOV/roll。起终点一致与平滑权重支持位置连续，不自动保证速度连续，也不自动保证路径安全；检查混合区的最拥挤状态。用大幅 FOV 变化来救构图前先调整轨迹和距离。

## 横竖屏计划与验收

采用本片记录的宽高（横屏通常 1920×1080，竖屏通常 1080×1920）；用竖直 FOV 和真实 aspect 计算投影，竖直 FOV 是相机参数，两种画幅都适用。横屏安排横向行进与关系展开，竖屏安排纵向层次与上下阅读区；跨画幅重新检查相机距离、路径、遮挡和出框，不简单裁切。把主体投影框/活动区、行进留白与字幕安全区分开设计；主体允许合理屏幕漂移，不强制永远居中。

镜头表的相机可以使用结构化对象，例如 `{subjectId:'bird-2', mode:'follow', position:'S(t-lag)+localOffset(t)', target:'S(t)+velocity(t)*lead', handoff:'到达出口后看向群体', screenRegion:'左中部，右侧保留行进空间', parallax:'近柱/远山', hold:'接触后短停'}`。这是设计信息，现有 shot_contract 的时间检查不证明摄影质量。

先验证最难的短窗：起步、转弯、最快速度、遮挡重现、跟拍→揭示或换目标。记录 C(t)、T(t)、主体屏幕位置/尺寸、背景标志投影、最小可见状态，再实际看连续序列。数值检查用于抓固定目标、出框、突跳，不能评分“灵动”。只有局部审帧时如实标明覆盖；完整影片需实际检查全片摄影节奏。

判断有效：主体确实在世界移动；相机真的跟随或以明确动机转向；前景比远景有更强相对变化；主体方向、身份与关键动作可读；转弯与接棒没有突然甩镜；停机有理解目的。修改后检查乱序时间和重复时刻，而不只实时预览。这个资源的本次验证状态以项目 `work/camera-upgrade-20261010/CHECKPOINT.md` 为准；未经测试的镜头类型继续按本片验证。
