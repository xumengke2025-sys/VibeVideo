## 结论与目标

采用一个制作主角色、按需一个创意导演、一个独立视听审片者，继承用户当前模型与推理设置。改善创意表达、动作表演与证据闭环，优先复用现有工程，不另搭动画或多Agent框架。

项目固定9:16、默认1080×1920，历史横版保留；每次生成预演、局部片段、正式片后，全帧视觉和完整音频审核继续适用。修复最多两轮，不能借换模型/重新分组刷新计数。用户明确要求先看时立即展示。

用户已撤销双模型配置环节。先前安装的三份项目模型配置移到历史归档，项目不再设置模型、推理档位或代理并发上限。activation/activation.json和config-draft仅记录此前实验；当前状态以activation/withdrawal.json为准。导演与独立审片职责继续适用。

## 2. 保留工作机制，取消模型配置

| 建议 | 决策 | 具体修正 |
|---|---|---|
| 主控负责工程、专家负责判断 | 采用 | 不让两个角色同时写共享代码；主制作负责落盘、集成和交付 |
| 导演和审片分开 | 采用 | 不让原导演承担自己的独立审片；独立性来自角色与观察过程，不要求不同模型 |
| 高价值节点才调用导演 | 采用 | 新片/重大重构调用，字幕参数、已定位穿模等不重复发散 |
| 控制专家调用次数 | 改为软预算 | 预演/样段/正式片/复核仍须审核；复用审片上下文，记录跟进与工具工作量，不能用次数跳过复核 |
| 审片只给少量关键帧 | 不作完整验收 | 给证据索引并分批访问全部帧；关键帧是导航，不是覆盖替代品 |
| 小改减少重复派工 | 按审核职责修正 | 可不请导演；新生成媒体仍需独立审核，相同片段复用需等同性映射 |
| read-only角色写报告 | 调整 | 真只读时返回结构化报告，主角色原样落盘；若仅指不改制作源码则明确qa写权限 |
| 两轮失败自动升XHigh | 不自动执行 | 有证据再评估重构，遵守上限和既有授权；默认交付当前状态，不继续无限升级 |
| 42/100演示评分 | 不作基线 | 附件中的数字是演示输入；本项目没有这项真实评分 |
| 全工程每次扫描 | 按需读取 | 读入口和必要源码，角色之间不复制全部终端日志；重要失败细节仍保留可追查路径 |

制作角色仍需理解设计意图和事实约束，发现导演方案不可实现或误导时返回证据，不能把交接理解为机械服从。所有角色继承当前模型与推理，不按旧草案切换。

### Functional Emotions：先确保形式正确

### ClaudeAnimationBase：把动作从数值变化变成表演

固定commit `0ac8bf2b31942376cb6b8c4074715595d512acd2`。直接研究关键姿态、情绪时间轴和跟随世界锚点的逐帧裁剪。本轮已将适用原则加入motion-craft，并明确视觉spring不是实际受力求解。

后续验证：飞行器选一个转弯/停等/通过动作，姿态与路径方向、速度或曲率保持关系，检查预备与恢复；阀门检查闭合、临界开启、受限行程和逆压关闭，禁止刚性件卡通挤压。跟随裁剪只用于细节，不能取代全局构图。

### twoclipping：继续应用已研究机制

原14秒UI已取样研究；本机8秒无声连续形态测试已运行并实际查看240帧。继续复用continuity.mjs，不重搜同一案例充当新成果。

后续验证：飞行轨迹与结尾路径关系，或流路/压力/受力关系，选择一种有题材意义的连续变化。记录持续对象、对应点/锚点、含义变化和接收状态，检查完整中间态。任意轮廓或字符变形、原作音乐同步尚未证明。

## 4. 一条作品的执行流程

1. **制作主角色收敛约束**：受众、事实、时长/画幅、表达形式、素材/声音授权及保护项。复用旧事实核验和接口，不重复扫全仓。
2. **按需导演定稿**：不同事件逻辑候选、选择理由、创意否决条件；沿用creative-direction与plan.json，给每镜的建立/变化/结果、reads、相机、因果响应和连接锚点。
3. **动态预演**：用低成本几何验证因果和构图。生成后独立审核，结论按预演目的判断，不要求占位材质达到正式画质。
4. **关键最终品质样段**：选最难完整动作及邻接转场，实际字体/材质/声音、最终画幅；简单短片可直接用整片。先处理该路线的严重问题，再扩展，不用静态风格帧替代动态证明。
5. **正式制作与工程检查**：确定性寻址、统一锚点、事实/接触约束、中文/布局、音画事件、完整解码。已有工具优先，必要时局部重渲。
6. **独立视听审核**：首次理解观察→符合性核对；每解码帧实际可辨认地查看，关键细节看原尺寸；检查整体动态及全音频。工具不能听音则如实incomplete；ASR/波形不当听感。
7. **按缺陷ID修复与复核**：预期改善X、保留Y；每版新哈希、相邻窗口与声音同步、新版总覆盖；不把修复引起的退化藏掉。最多两轮，必要审核不因软预算减少。
8. **直接交付**：可播放媒体、源码入口、简短审核结论与限制。达到上限或能力不足仍展示当前可播放版本，标注未通过/未完成。

角色交接文件采用现有文件而非重建格式：brief/creative-direction（定稿）、plan.json（镜头/事件）、qa/<version>/av-review.json（观察）、修复记录（ID/前后哈希/保护项）、运行记录（角色/模型证据/时间/成本可观察性）。

## 7. 创作质量与额度怎样测

后续用同一模型/推理/时长/素材/预算比较旧方法和优化方法，检查创意与制作改进是否进入成片。不安排双模型对照，不用模型更换解释质量变化。

正式A/B保留原源代码和渲染文件，版本随机标记A/B；若能获得不了解版本的人评审，记录偏好及具体时间码，避免只用制作模型自评分。已看过详细解释的审片者不能假装首次理解。评价以题材目标为准：飞行器意图/反馈/记忆点，阀门机制理解/接触/信息层级；参考片的特效数量、持续运动比例、分数总和不是通过条件。

| 指标 | 记录规则 |
|---|---|
| 创作判断 | 首次看懂的变化、未懂处、明确时间码偏好、否决条件是否触发；未开展则pending |
| 工程 | 尺寸/时长/帧数/完整解码、状态与像素确定性、机械约束、实际严重问题 |
| 审核 | 总解码帧/已观察范围/大图检查/动态方式/完整听音/工具限制/当前哈希 |
| 资源 | 导演/审片角色启动与跟进次数、可得模型与档位元数据、生产/渲染/审片各自耗时 |
| 额度/费用 | 只填真实可观察tokens/费用；只有账号总额度时不推算单片成本，不拿API价代替订阅额度 |
| 返工 | 轮数、主要缺陷关闭情况、保护项是否退化、最终用户偏好 |

成本不可用时照样比较时间、重复派工和返工量，但不能承诺节省50%/80%。读全部帧的成本要单列，不能藏进一次“审片调用”。无声实验不证明音频能力；有声验证要有实际感知工具，否则如实停留在审核未完成。
