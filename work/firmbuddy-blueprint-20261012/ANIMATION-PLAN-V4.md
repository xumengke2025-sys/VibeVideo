# FirmBuddy 动画重制计划

本片面向券商客户经理与业务负责人，讲清 FirmBuddy 如何把市场信号和业务问题转成有依据的服务方案与持续跟进行动。复查后改为三个场景各自完成“问题—处理—结果”，以同一个示例议题连接观看体验，但三种场景都可以独立进入。图纸上的变化承担解释，旁白补充含义。

目标规格：1920×1080 横屏，30 fps，约68秒。整片发生在同一张蓝晒工程图纸上，不出现人物、手、人物剪影或真人专家。片内创意标题为《把问题展开成行动》。本轮交付制作计划，尚未开始 V4 动画编码或渲染。旁白录制后在约65–70秒内调整动作时间，保持阅读停留。

## 核心表达

产品定位：面向券商展业与企业客户经营的 AI 专家协作平台。

观众依次理解：这是券商客户经营的 AI 专家平台 → 查商机时能发现线索、分工研判 → 有疑问时能按资料和条件回答 → 准备拜访时能形成具体提问与材料 → 跟进记录还能帮助调整行动 → 这些能力服务于更广的客户经营。

三种入口始终保留身份：S 商机查询、A 业务答疑、V 拜访准备。它们共用专家、工具和知识能力，但按需要选择处理方式；单个问题可以由一位专家回答，复杂问题才组织会商，不暗示每次提问都要启动全体专家。

最终应让观众记住：“FirmBuddy，把业务问题变成有依据的行动。”三个记忆点是专业分工、知识有据、持续经营。专家规模和功能广度作为这三个特点的支撑，避免每个功能都争夺一次主讲。

## 本次复查修订

- 原案6–41秒只追随商机，答疑与拜访随后直接出成果：改为商机、答疑、拜访依次各有明确输入与处理动作，取消末段重复罗列三份成果。
- 原案的引用只证明“查过资料”：改为证据暴露信息缺口，直接改变建议和拜访提问。观众必须看见检索前后有何不同。
- 原案“文档进入装备再进入专家”混淆配置与运行：已装配关系在镜头开始前成立，本次只演示范围内检索；知识管理和版本关系作静态剖面。
- 原案8秒内读四个专家和四个子问题过密：广场展示规模，前景只展开行业、财务、资本运作三种职责；合规等其他专业保留广场索引，不暗示全体同时会商。
- 原案结尾需要靠小字证明功能全：把功能索引与最终品牌分成两次停留；最终只要求读品牌、三阶段和一句价值主张。

## 创意选择

| 候选 | 核心事件与体验 | 关键镜头 | 实现难点与取舍 |
|---|---|---|---|
| 三条问题展开同一套专业系统 | 三个问题接入共同底座，在需要处展开分工和依据，最后得到各自结果；观众看懂产品怎样工作 | 选中专家席位抽出工作分支，知识引用返回判断，三个成果在各自出口落定 | 需要稳定对象身份和分支时序；现有二维相机、描线和遮罩可支持。采用 |
| 一个服务方向被证据收敛 | 初步服务假设经检索发现信息不足，形成具体核实问题 | 未定的“融资服务？”收束成“先确认资金来源与缺口” | 纳入答疑局部事件，示例全程标明；不虚构产品先给了错误结论，不演成风控纠错片 |
| 企业跨年成长，专家随阶段接力 | 企业从上市前走到上市后，不断形成新需求；观众理解生命周期覆盖 | 一条企业成长路径依次接入业务条线 | 时间跨度大、易虚构企业故事；68秒难解释知识与工具机制。只将全生命周期用于结尾揭示 |

选择第一种，吸收第二种的局部证据事件。视觉母题是一根不断获得依据与分工的制图引线。S/A/V只作制作对象ID，成片始终显示“查商机／问业务／备拜访”，不要求观众记英语缩写。三个场景切换时都出现一次新的自然语言输入，明确可以独立使用；不把查商机画成问业务或准备拜访的前置条件。

## 美术与构图

纸张采用深普鲁士蓝，中心有柔和晒印差异，涂布刷痕横向延伸，纤维与折痕固定在纸面坐标。保留 V3 已有的材质增强，调整其局部强度：阅读区域低干扰，空白和近景边缘可见纸浆纹理。纸纹不随时间抖动，不用整屏颗粒掩盖结构不足。

主结构为偏暖的蓝白线，辅助结构降低明度；线宽分轮廓、内部结构、索引和施工线四级。沿用参考的 zoom^0.65 线宽补偿，避免近景粗线膨胀。全片色彩主要由蓝与白承担，状态使用轮廓、虚实线和准确文字区分，不使用“审核通过”或“合规批准”印章。

构图轮换四种关系：开场提问与输入栏、纵深阶梯状的专家广场、侧向展开的知识剖面、沿同一基准线对齐的拜访问题与依据。用一条2–3秒的停机阅读节拍，交替1秒左右的选择、展开和接合动作；速度来自删掉重复讲解，不压缩中文阅读。背景始终属于同一张图纸。

采用近正俯视为主。知识层和专家工作分支可有轻微斜投影厚度，属于工程图示，不变成漂浮的三维界面。纸面无霓虹、无全息屏、无凭空飞出的实体。跟随路径时运动方向清楚，读证据与结论时相机停住。

中文主标签48–60px，关键短句40–46px，来源与版本近景标注至少30px；远景小字只构成索引密度，不承担必须读懂的事实。字号均指成片屏幕尺寸，编码时按最终投影反算。左右至少96px、上下至少64px安全边距，字幕区与关键主体分开登记。

字幕沿用 NOTE 制图注释框，但每镜只占预留留白，完整句出现后保持足够阅读时间。字体使用工程已有中文字体和等宽编号；准确测量中文，不逐字弹跳。主要说明同时最多三个短标签，长专家名称以已核对的简称显示。正文解释由旁白承担，画面只留关键词与证据；完整字幕最多两行，不与另一段同义长说明叠放。文中“流程示例”须在示例局部持续可见。

## 三个值得记住的视觉动作

1. **从广场选出分工。** 专家席位不是点亮后结束：被选中的席位沿各自引线展开为不同工作分支，观众看到为何选他们、各自回答什么。席位一直留在原处，不能把名字换成一组通用图标。
2. **依据把空泛方向变成具体问题。** 档案剖面显出已成立的知识装配关系，当前动作是检索与引用。证据返回后，“融资服务？”收敛为“先确认资金来源与缺口”；这个缺项又在拜访页对齐成为“资金怎么安排？”。同一对象的形态变化负责解释，不只用连线象征智能。
3. **把局部揭示为全景。** 最后不是换一张生命周期表，而是拉远露出同一张图纸上一直存在的服务地图。原来的问题、专家、证据和成果仍然连在一起，结尾兑现“广泛支持持续客户经营”。

额外的小巧思：待确认需求使用未闭合轮廓和虚线；用户确认的是跟进行动节点，不能把它误读为客户已经确认需求。反馈沿反向细线回到下次行动，视觉上形成经营循环。

## 世界布局与连续交接

图纸建议采用约7600×4400世界单位，工作剖面处于上市后区域，但不是整个产品只能服务上市公司；全景同时保留上市前和上市中入口。布局按实际输出构图校准。若纸面全宽投到1728px安全区，缩放约0.227，则必读48px标题需约211世界单位；不能直接沿用近景字号。末镜只保留三阶段大标签，业务条线与旧流程降为结构线；禁止用缩小字体塞完整表格。

输入区在西北，监测在其东侧，专家广场在东北；答疑与知识剖面位于广场下方，拜访页在中南，跟进反馈沿南侧返回。三种成果在各场景结束时留在原处，55秒退到索引层才见它们的整体关系。切换场景时允许同纸面的短匹配剪辑，通过相同议题标记交接，不要求每次沿线旅行；最终两次后退均保持世界坐标连续。

| 交接点 | 保留锚点 | 切前、切中、切后可读状态 |
|---|---|---|
| 6秒 | 查商机输入与请求引线 | 问题已读 → 资料带筛选 → 候选带来源和待核实状态 |
| 15秒 | 扩产议题与来源端口 | 候选已读 → 对齐专家议题中心 → 按职责分工，不成为已确认需求 |
| 24秒 | 同一扩产议题标记 | 商机结果保留 → 匹配切到问业务的新输入 → 一位专家检索；明确独立入口 |
| 36秒 | 资金安排缺项与引用标记 | 有依据的回答停留 → 拜访新输入 → 缺项与提问同形对齐，不把两次请求合并 |
| 46秒 | 拜访策略包的跟进端口 | 提问读完 → 用户确认 → 待跟进任务建立 |
| 55秒 | 下一步行动与三场景结果 | 下一步已读 → 后退一级 → 两组功能索引依次可读 |

运动段的主体是描线前沿或实际移动的档案图层，不是整张背景。主体路径、相机中心和关注锚点均从绝对时间采样；相机略向前留出引线生长空间。档案页移动时让专家分支保持世界位置，形成可见相对运动。关键接触和阅读停机，不使用惯性甩镜或弹簧式相机回弹。

- 扩产议题、项目资料、跟进记录及回答均是说明机制的虚构流程示例，画面持续标注“流程示例”。示例资料仅写“扩产计划；资金安排未提供”，不伪装真实公告、法规原文或已运行出的产品结果。示例引用标记写“示例资料”，不伪造真实来源ID。“融资服务？”只是初步假设，未确认需求始终不闭合。
- 知识的价值是可装配、可检索、可引用与版本管理。档案密度是视觉示意，不虚报生产文档数量，不宣称未接入的案例库已经存在。

- 业务全景表示服务入口与协作范围，不等于所有业务已有专属专家、所有数据源在线或平台自动执行金融交易。

## 声音与节奏

旁白为主时钟。清晰、自然、克制，分句有呼吸；目标约每秒4个汉字，不沿用机械压缩整片旁白的做法。实际录音后先排理解停留，再调整非阅读段速度。

制作时核实可用配音路线。若仍使用系统语音，先用“券商客户经营、AI专家、资金缺口、FirmBuddy”做短句听音确认；无法自然读出英文品牌时品牌只留画面。旁白避免“智能组局、Active Loadout”等内部术语。听音工具不可用时记录范围，由用户反馈，不将音量检查当听音。

音效主要为绘图笔、纸页轻擦、节点接合的短声。扫描段稍密，证据和判断段减少声音，成果落定有轻而明确的收束。配乐采用有授权来源的克制器乐，或清楚标明原创合成音床；不把当前合成音轨称为专业录音配乐。避免每个标签都配重击或同一提示音。

## 后续制作顺序

1. 在现有工程内建立 `v4/` 独立入口与事件数据，保留V1–V3成片、源码和当前入口。共享纸面、字体与渲染器，重写V4主体与时间轴。
2. 制作真实低清动态预演，验证三个独立输入、专家分工、依据改变建议以及最后两次后退。像素缓冲真实降低，不仅CSS缩小。动态预演优先验证24–46秒是否能看懂，不以静态美术板替代。
3. 完成24–46秒答疑到拜访的样段，并包含相邻交接；使用1920×1080、正式字体、材质和声音。重点看知识配置与检索能否分清、资料缺项如何变成结论和提问、遮挡是否正确、结果是否来得及读。只由制作角色作内部判断。
4. 按同一事件表扩展全片，旁白、字幕、相机与动作统一秒时钟；重要文字登记投影框、允许遮挡与安全区。检查极端近景、交接中间态和68秒结尾停留。
5. 导出MP4及源码，做画幅、时长、音轨、完整解码和可寻址检查；具体画面观察、连续窗口与听音如实记录。沿用已选 `delivery_mode: ai_review_once` 及已用预算，不自动新增全面审片或导演角色。

本计划的高风险动作：17–21秒专家分工、27–36秒知识剖面与依据改变建议、39–42秒缺项变提问、55–68秒两级全景揭示。计划验收问题：前三秒是否知道服务对象？三个场景是否都看到输入和结果？能否说出依据改变了什么？最后是否记住分工、有据和持续经营？这些仍需动态样段证明，本次不宣称审美或视听验收通过。
