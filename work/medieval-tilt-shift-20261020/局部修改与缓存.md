# 后续修改不默认重渲全片

先保留完整且通过工程检查的成片及其逐帧底片，再处理局部修改。`shot_cache.py` 将完整底片登记为不可覆盖的镜头缓存，按帧保存哈希。`plan` 必须明确选择局部镜头、全局画面改动或仅音轨改动，不根据 Blender 文件整体哈希变化自动让整片失效。

当前限制：完整 v13 为 76 秒，不含骑手；90 秒 v15 只有 107 帧，不能拼成完整骑手底片。正在运行的 v16 将补齐这份底片，已经生成的 v16 帧继续复用，不为缓存工具重启当前任务。完整 v16 通过工程检查后，`prepare_final_evidence_v16.py` 会登记 `render/shot-cache-v16.json`。

## 具体修改

- 仅换音乐或调音量：使用 `remux-audio`，视频流直接复制，三维渲染帧数为零，输出新文件并检查音轨解码。
- 局部镜头、建筑、人物或动作：先核对改动在其他镜头中的可见性、阴影、反射和间接光，以及动作与相邻切点。用 `plan --shots` 指定受影响镜头，默认加前后各两帧边界，只渲染计划中的帧。
- `materialize` 验证所有复用帧哈希、补帧是否齐全及画幅，组合出供编码使用的新目录，原底片不覆盖。保存逐帧来源后再合成完整 MP4，复核改动段和相邻镜头。
- 全城光照、全片摄影、整体画幅或全局材质等确实影响全片的改动：才使用 `--global-visual`。

`--shots` 是制作方根据实际证据作出的范围声明，工具本身不是自动可见性、阴影或反射判断器。宫殿不应未经检查就只声明 25–31 秒受影响，其他能看到宫殿及其光影的镜头也要列入。

## v16 镜头缓存边界

| ID | 时间 |
|---|---|
| 0 | 0–8 秒 |
| 1 | 8–19 秒 |
| 2 | 19–25 秒 |
| 3 | 25–31 秒，宫殿展示 |
| 4 | 31–44 秒 |
| 5 | 44–55 秒 |
| 6 | 55–64 秒 |
| 7 | 64–74 秒 |
| 8 | 74–81 秒 |
| 9 | 81–90 秒 |

例如确认只有 ID 3 受影响时，计划为 148 帧（含相邻四帧），其余 2012 帧复用；不是重新渲染 2160 帧。这个数字仅说明缓存计划，不能替代实际影响范围检查。
