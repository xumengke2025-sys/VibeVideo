# 独立逐帧视听审核

每次生成预演、局部片段或正式片后，在向用户交付前执行。用户明确要求先看当前版本时立即展示，标注尚未完成审核。此流程不改变用户的画幅、创作方向或工具授权。

## 两个角色与交接

长片与耗时优化另读 [review-performance.md](review-performance.md)。交接材料可一次准备在本地，审片者先保存盲看理解再打开brief；不必等待制作方第二次发送。按连续小批保存实际覆盖和缺陷，图片上下文膨胀时用紧凑记录续接剩余范围，保留首次理解与已有修复轮数。已有证据索引有效时不重复解码导出。

制作角色负责设计、实现、导出与修复；审片角色负责观察输出、核对内容、提出有证据的缺陷及复核，不直接改制作源码。优先使用独立 Codex 子代理，继承用户选定模型与推理设置，以最少上下文启动，避免带入制作角色的自评。不能使用子代理时可切换为单 Agent 的第二角色，但必须写明“同一 Agent 角色复核，非独立审核”。

分两步交接同一审片角色：首次只给本文件、visual-review.md、成片绝对路径与 SHA256、受众/题材/画幅和证据目录，让它记录实际看懂的事件与困惑；先不提供详细剧情解释。完成首次理解观察后，再给简短 brief、用户约束、脚本/字幕、镜头与声音事件表及事实来源做符合性审核，具体见 [production-quality.md](production-quality.md)。不附制作方自评分或“已经修好”的结论。审片者可运行证据提取，只在指定审核目录写报告；首次观察后再查源码定位原因。沿用同一审片者的上下文与原媒体证据，不为这两步重复导出或重看已完成的细节检查。

可用派工文本：

> 作为独立视听审片者审核指定成片。先阅读 independent-av-review.md 与 visual-review.md，先不读详细剧情解释，记录实际看懂的事件及困惑，再接收 brief/镜头表等材料做符合性审核。用 Codex 视觉能力实际查看覆盖全部帧的分页证据，对细节查看原尺寸图；按连续时间段检查动态并听完整音轨。记录文件哈希、实际覆盖、工具限制、带时间码的缺陷和交付结论。只写审核证据与报告，不修改制作源码；未看到或未听到的内容不得推断为通过。

## 逐帧画面：导出不是看过

1. 制作角色先检查文件存在、完整解码、分辨率、帧率、时长及预期音轨。使用实际解码帧数与媒体时间戳；可变帧率不能用帧号除以名义 fps 冒充精确时间。
2. 用 `frame_audit.py` 导出全部解码帧与分页接触表，按连续帧区间分批交给审片者。不得只抽关键帧或均匀采样后宣称逐帧审核。长片分批持续推进，维护已审、待审区间，不因为上下文或耗时自动降低覆盖标准。
3. 用当前环境可用的图像查看工具将每页实际送入 Codex 视觉理解。接触表用于覆盖和发现异常；文字、机械接触、穿透、边缘和疑似闪帧必须打开原尺寸帧，检查异常前后连续状态。缩图不可读时补看大图，不能登记为已确认。
4. 检查事实与因果顺序、字幕/标注准确性和可读性、主体完整性、遮挡/穿透、画面抖动、闪烁、材质与光照连续性、转场中间态、构图与注意力。机械/科学内容结合来源检查，视觉合理不等于事实正确。
5. 另按正常速度播放并实际观察动态；若工具不能让模型感知连续播放，使用有时间戳的连续帧序列检查顺序与变化，明确正常速度观看未完成。打开播放器或生成播放链接不算模型已看过。静态帧覆盖不能证明节奏与运动观感通过。

逐帧完成意味着每个解码帧都属于审片者实际看过且可辨认的证据范围；机器帧差、OCR、黑帧检测和提取日志只作辅助。支持逐帧并不意味着必须一帧一次工具调用，可用清晰的分页序列批量观察。

## 音频：独立的完整时间轴

视觉能力不能直接证明声音正确。先核实当前模型/工具能否把实际音频提供给审片者感知；不要把本机扬声器播放、音频链接、波形或转写当成听过。无法实际听音时完成可做的检查，报告“听音未完成”，不宣称完整视听验收通过，也不擅自上传到外部服务或切换模型。

能听音时，提取当前成片音轨，按连续时间段听完整音频，交界适度重叠以检查断字/爆音。音频以时间段覆盖，不使用没有意义的“逐视频帧听音”。核对实际旁白与批准脚本的错读、漏字、重复、事实错误，检查语速停顿、音乐遮盖、突变/失真、意外静音、首尾截断，以及声音事件和画面动作/字幕的同步。转写与响度检测用于定位，听感仍来自实际音频。

有意无声的作品将听音项记为 `not_applicable`，说明 brief 依据；应有声音却缺音轨属于缺陷。

## 证据与结论

在项目 `qa/<version>/` 保存 `av-review.json` 和简短可读报告，与既有 `creative_review.py` 日志并存。后者的校验不能代替独立审核。建议结构：

```json
{
  "video_path": "absolute path",
  "video_sha256": "actual hash",
  "reviewer": {"mode": "independent_agent", "id": "actual reviewer id"},
  "coverage": {
    "decoded_frames": 0,
    "visual_ranges": [],
    "unreviewed_frame_ranges": [],
    "realtime_viewed_ranges_seconds": [],
    "audio_listened_ranges_seconds": [],
    "audio_status": "pending"
  },
  "findings": [],
  "limitations": [],
  "verdict": "incomplete"
}
```

帧范围含首尾且从 0 开始；每个已审范围附实际查看的证据文件、观察方式及具体发现。音频范围以媒体时间为准，覆盖到结尾。缺陷记录 `id / severity / frame_range / time_range / evidence / observation / impact / proposed_fix / recheck_status`，声音问题可仅填时间范围。区分 `blocker`（事实错误、关键机制错误、关键内容缺失/不可读、旁白错误等）、`major`（明显损害观感或听感）、`minor`（局部优化）。少于三处问题时不要凑数。

结论为 `pass / needs_revision / incomplete`：只有覆盖完整、必需视听检查完成且无未解决 blocker/major 才可 pass；未完成的模态、区间或事实核验写 incomplete；已证实的严重问题写 needs_revision 并保留覆盖缺口。主 Agent 核对覆盖区间无遗漏、证据可访问、哈希对应当前文件，不能仅接受审片者一句“通过”。新增 `scripts/check_av_review.py` 可核对声明范围、当前媒体哈希、解码帧数、证据文件及严重缺陷状态；它不能证明真的看过/听过，也不替代整体动态、知识和创意验收。

使用校验器时，`visual_ranges` 每项写 `{start_frame,end_frame,evidence:[绝对图片路径],method,observation,source_video_sha256,evidence_sha256:{证据路径:实际哈希}}`；`audio_listened_ranges_seconds` 每项写 `{start,end,evidence:[绝对音频或视听文件路径],method,observation,source_video_sha256,evidence_sha256:{证据路径:实际哈希}}`。音频method只允许真正的`audio_input`或`perceptible_av_playback`，另写`coverage.audio_perception:{status:"available",tool:实际工具}`；工具无法感知时填unavailable、audio_status pending，不能拿ASR或波形补成complete。音频覆盖按完整音轨时长核对，包括可能超出视频流的部分。哈希绑定与后缀检查只能发现声明矛盾，不能鉴定媒体内容或证明真实感知。

观察内容必须由审片者产生；未完成范围保持空或待审。命令：`python scripts/check_av_review.py final.mp4 --review qa/av-review.json --ffprobe <实际路径> --out qa/av-consistency.json`。brief 明确要求无声且实际没有音轨时才加 `--allow-silent`，听音状态为 `not_applicable`。这不是兼容转换器，旧日志缺少字段时保留原件并报告未满足新校验，不能自动补造。

整体创意另核对定稿的“即使技术精致也不符合目标”条件：表达形式、核心事件或结尾承诺明显不成立时登记 major，指明观察依据和需要重构的部分，不以没有穿模/错字替代创作通过。按 [role-orchestration.md](role-orchestration.md) 精简交接，不精简实际审核覆盖；不同模型不是独立性的必要条件。

## 修复、复核与交付

除两轮修复上限外，按review-performance的默认10分钟无实质进展软边界交付当前版本，标明审核未完成并保留晚到报告。无法实际听音时不持续等待不存在的能力。暂停期间不计超时，不能为了交付边界杀掉正在有效工作的进程。

制作角色按缺陷 ID 修复，每轮优先处理最影响理解和观感的问题，保留旧版。默认最多两轮修复后复核，用户另有要求从其要求。新成片必须以新哈希审核；复用完全相同的帧/音频片段证据须有机器等同性与映射记录，单凭“只改局部”不能沿用旧结论。对修改处及相邻镜头、音画同步进行重点复核，同时完成新版覆盖。

每轮记录预期改善与应保留的优点，按 production-quality 对比同一动作窗口；检查修复是否让主体变小、阅读停留不足、节奏拖慢或混音退化，新问题也登记为缺陷。首次理解观察保留原记录，已读过解释的同一审片者不能在复核时声称自己仍是首次观看。

通过后直接展示可播放成片，附一两句审核范围与修复摘要。到达返工上限、重复相同失败或感知工具不可用时，停止盲目返工，展示当前可播放版本并明确标注“未通过/审核未完成”，列出剩余问题和限制，不藏片、不假报通过。用户此后反馈进入针对性修改。
