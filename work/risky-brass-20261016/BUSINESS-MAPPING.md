# 从 Risky 的实际操作到机械动画

本文件是制作依据。产品事实来自本地实现；机构是解释方式，不是产品界面，也不是实际运行结果。本次只读取业务源码，不修改业务项目。

## 影片要讲清楚的事

用户围绕一家公司的一件事查资料、找关系、请专家讨论，再换条件看看可能影响谁，最后带着结果和疑问回去复核。同一案件匣A17始终保留，不能剪成六个无关功能展台。

| 用户在做什么 | 黄铜机构怎样演示 | 面向用户的短句 | 实现依据 |
|---|---|---|---|
| 先选准公司和事件 | 公司铭牌与事件卡插入同一案件匣，主体身份锁定后才能前进 | 先确认是哪家公司、哪件事 | README.md:5；risk-context-exporter.mjs:19-21 |

## 替换三表盘的样段

三台同构试验架保留相同的示例借款公司A、担保方B、集团企业C，以及同样的关系。示例起点是A出现偿债压力，B为A提供担保，B与C同属集团；压力情景假设融资更难，缓释情景假设获得资金支持。公司与关系全部为合成例子。静态杆代表例子中确认的关联；运动标记仅代表本片编排的假设影响，明确标为示例，不冒充实际引擎日志。

- 按现有情况：A已有事件，后续仍可变化；不再重复添加同一冲击。不能画成“零风险”或完全不运行。
- 情况变差：只在起始公司A增加压力，再逐步展示A到B、B到C的示例影响。不能让所有公司同时变红来冒充路径。
- 采取措施：仍以同一已有状态开始，在A上加入缓释假设，压力减轻；保留关系，不画硬闸切断连线，也不承诺所有公司恢复正常。

示例不使用未经运行的分数、概率、损失或“精准预测”等结论。降低幅度和涉及范围仅为动作示意。三台是比较的视觉并列；普通操作一次确认一个情景，高级分析另经确认运行，不表演“打开案件即自动三路出结论”。

## 用语标准

一句话只讲一件用户关心的事，以“公司、事情、资料、关系、影响、措施、结果、复核”作为主要词汇。专业名词只在确实必要时出现，并配简单说明。设备上优先放有意义的中文铭牌，不把英文缩写当信息。

| 内部术语 | 片中优先表达 |
|---|---|
| 主体锁定 | 先确认是哪家公司 |
| 证据链 / 溯源 | 资料从哪里来 |
| 上下文贯穿 | 始终围绕同一件事 |
| 冻结快照 | 固定这次使用的资料 |
| 基准 / 不利 / 缓释 | 按现有情况 / 情况变差 / 采取措施 |
| 传播拓扑 / 高阶关联 | 通过哪些关系影响谁 |
| 业务与舆情双轨 | 公司怎么应对，消息怎么扩散 |
| 模型参数 / 条件冲击 | 这次试验设定的条件 |
| 审计 / 决策归因 | 每一步都能回头查 |

短提示使用“示例演示，不是实际预测”。文字辅助动作；不能靠长字幕补救看不懂的机构。
