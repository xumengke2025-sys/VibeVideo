# 从参考成片反推制作能力

适用于用户给出作品链接、指出质量差距，或要求接近某个作者的制作水准。先理解用户喜欢的实际片段，再决定制作路线。清晰的抽象线稿也能精细；画面复杂度、位图写实程度和制作完成度分别判断。

## 证据怎么取得

取得视频的实际画面与时间轴，不用标题、封面或作者宣传代替看视频。先覆盖整片的抽帧，再加密分析有代表性的动作；记录源分辨率、读取分辨率/帧率、时间范围、是否实时观看/听音。公开取不到高清时可以分析构图与动作，细节结论需用原尺寸输出或源码补证，不把放大的低清图当高清。

有开源项目时读 treatment/style bible、timeline、音频/台词数据、代表场景、字体与渲染模块；保存 commit。说明看到的是原作品、转载重渲版还是当前源码输出。第三方代码可按许可证研究和复用；歌曲、角色、字体等可能另有权利。源码复现用于验证工具，不能宣称为自己的新作品或已经具备跨题材创作能力。

## 把「厉害」拆成可实施关系

| 分析项 | 问什么 | 写成制作决定 |
|---|---|---|
| 主动作 | 观众看到了哪一个意外但合理的变化？ | 描述对象如何改变含义，而不只写入场、缩放、淡出 |
| 连续关系 | 哪个点、线、轮廓、方向或对象从前一状态保留到后一状态？ | 指定连续锚点；允许剪辑，检查切点是否仍能读懂 |
| 场景深度 | 相机换位后，遮挡、透视、前后层次如何改变？ | 为真实转向/穿行建立几何或视频；平面图用于其能支持的动作 |
| 文字作用 | 字词是标注、被操作的对象，还是世界中的标牌？ | 准确测量整句，保留分词接缝字距，按语义设置变形与位置 |
| 时序 | 哪个词、重音、接触或鼓点触发变化？ | 以声音事件/机制事件锚定动作，另留可读的结果停留 |
| 美术系统 | 多镜头为何仍属于同一作品？ | 共享字体角色、光照/线条规则、色彩功能与复现母题；题材决定具体风格 |
| 渲染质量 | 哪些缺陷发生在运动/高分辨率中？ | 检查细线闪烁、纹理游泳、模糊重影、字形接缝和色彩一致性 |

## 本次 pdoom 研究形成的经验

研究来源：[mexicat/pdoom-video](https://github.com/mexicat/pdoom-video)，commit `fa164b74fd0b26a99375715b619c55b4a0fb3d05`（2026-10-06 05:24:56 +08:00）。用户提供的 B站转载 [BV18ta86EEHb](https://www.bilibili.com/video/BV18ta86EEHb/) 说明它是参数重渲版；该片发布 09-27，用户后续明确选它为参考。参考时间范围应服从这项后续选择，勿以最初 09-30 的研究偏好将其排除。

- **约 10–16 秒：曲线下坠进入地形。** 已看连续抽帧，源码 `loss.ts` 让图表高度与地形共用 log 尺度，相机沿下坠点从图表飞入三维峡谷，再换位展示最低点。精彩来自叙事、几何和相机的协同；并非给一张地形图片推镜。该地形是歌曲的视觉比喻，不是实测损失数据。
- **约 30–34 秒：扫描面具，揭示内部。** 已看加密抽帧；`shoggoth-glsl.ts` 先生成 SDF 体积/深度与表面坐标，再按管体方向着雕刻线、光照与遮挡。可迁移的是材质细节服从形体，以及扫描/剖面真的揭示被遮挡的结构；不要求科普片都画怪物。
- **约 82–87 秒：路径急转、地图拉开。** 路径、文字和相机一起转向，原本的地形最后显出一个完整形状。动词驱动运镜，注意力始终有锚点；高速只用于关键改变，之后停留读懂结果。
- **整片的橙色点与线。** 在不同场景充当绘图笔、曲线、光信号、物体轮廓和导火索。共享母题建立连贯性，各场景仍有自己的材料与构图。不要把每幕锁进同一种大标题+配图排版。
- **文字即场景。** 逐词时序、宽度/重量变体、路径排字、标牌与遮挡一同参与。`type.ts` 的 `layout/glyphX` 保留拆分绘制时的 kerning；中文字不直接照搬 Archivo 的英文宽度轴，要选择可用字体并看真实中文排版。
- **声音是时间结构。** 仓库已提交对齐后的词/部分音节、beats、downbeats、onsets 和声部包络，`timeline.ts` 用歌词查询和拍点确定镜头。MV 可逐词+拍点；旁白科普先对齐重音、因果事件与段落，不强迫每词弹出或每拍硬切。
- **完成度来自修订。** 当前仓库记载多轮调整，包含替换怪异眼睛、取消常驻角落读数、重做镜头、字距和高分辨率线宽等。只读成功提示词不足以复现这些选择。

另一个用户参考 [BV1vRHa63EYg](https://www.bilibili.com/video/BV1vRHa63EYg/)（10-03）展示分镜、音乐时间轴、代码层转换成画面、分镜并行、合成与检查。实际抽帧可见像素角色、字体、暖色与模块转换保持一致；没有取得原工程，不以画面上的「一句话」说明推断实际对话/人工工作量。

## 细线与高速动作的条件检查

需要类似线雕/空间穿行时，按瓶颈考虑 GPU 线批次、屏幕导数抗锯齿、SDF 或真实三维；不默认把所有片子都改用复杂着色器。细节需有主次，远景密集线场可降低密度/对比，主体轮廓保持稳定。

提高输出分辨率时保留逻辑坐标与物理像素的区别。纹理、字体 atlas 和 render target 应同步到目标尺寸；基于 `fwidth` 的线宽与抗锯齿须核查放大后视觉重量，不能只把输出分辨率改成 4K。

快速运镜需要时间采样时，在明确快门窗口内积累子帧，再做稳定的文字/颗粒等后处理。`shutter` 的单位是帧间隔的比例，不是秒。姿态由时间直接计算，离散闪烁/随机状态以显示帧锁定，避免一帧叠出两种状态；硬切须隔离时间采样。先对短窗口检查条纹、字影与主体可读性，测成本后再加采样，不照抄原项目 108/324 子帧或把截图重复混合冒充真实快门采样。

## 将差距写成片段验收

选择当前作品最弱的一项，做能完整表现变化的短片段。记录：`表达的关系 / 起点→变化→结果 / 连续锚点 / 几何与素材需求 / 字词作用 / 相机动作 / 声音或事件锚点 / 中间态检查`。保留参考的有效关系，独立设计题材和画面；不要以复制原项目一段渲染结果宣称新流程已能原创同等作品。

0.2 星云样片仅证明混合素材与审帧工具跑通；精细概念装置与简单影像层归位还未验证 pdoom 所展示的空间叙事和连续变形。后续目标应把这两类动作实际做出来，再判断画质提升，而不继续只增加细节位图。

## 本机复现范围

当前源码的 `loss` 与 `shoggoth` 已实际渲染 1920×1080 代表帧，并导出原片 10–14 秒的 4 秒无声研究片段（120 帧、30fps、4 子帧采样），完整解码通过；查看了五张原尺寸设定帧和片段接触表。这是原作者场景的本机复现，未包装成 Codex 新创作品。

同一时刻 11 秒分别用 4 与 36 子帧渲染并查看：低采样时移动刻度有清楚的分身，高采样时变成连续模糊。该测试说明快门采样需要实际看图；不证明应把所有画面模糊化。采样增加的渲染成本没有有效基准测试，不能用首次编译与后续调用耗时作性能对比。未验证原作者完整 4K60、自适应采样或全片声音。

本次研究文件位于 `work/reference-study-20261008/`；`review-evidence.json` 记录实际取样、版本、图像检查与限制。Windows 临时测试只调整运行依赖与离线调用入口，场景源码保持原样，原包清单已恢复。
