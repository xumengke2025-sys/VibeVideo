# 一份事件表驱动画面、声音与字幕

选择旁白、音乐或动作中的主时钟，再把时间写成秒；帧号、音频采样点和 SRT 毫秒只在各自输出边界换算。实际旁白有语速和句间停顿，不能用估计时长当作录音已测时长。

## 可执行例子

在 `assets/style-studio/clips/one-way.json` 中，打开事件同时定义：

```json
{
  "id": "open", "at": 14, "duration": 1.5,
  "anchor": "valve-disc",
  "action": "正向压差增大阀瓣右移",
  "result": "弹簧压缩与通路打开",
  "sound": {"kind": "flow", "duration": 6.5, "gain": 0.13}
}
```

画面用 `progress(plan, 'open', t)`；拟音用同一事件的 `at + sound.offset` 转采样点，默认 offset 为 0；接触声的 offset 可等于动作 duration，让声音落在接触完成时。字幕引用 `event: 'open'`，起点与事件对齐。阀瓣状态驱动弹簧、流动和 Δx，两套端点不能手填。

JSON 是当前 Canvas 示例的契约，不强制其他工程采用这一文件格式。Remotion 可从相同数据构建 Sequence/声音轨；既有工程有成熟时间轴时增加必要字段，避免双份事实源。

## 需要保持的关系

- 每个关键事件说明对象、变化和可读结果；时间有单位、合法范围和稳定 id。
- 字幕先检查文本完成出现后的阅读时间，再检查主体遮挡。示例中文预算为字数 / 4.5 + 1.5 秒，属于保守起点，可根据观众、实际旁白和版面调整。
- 接触声按实际接触安排；流动等连续声可跨多个动作。不要求所有装饰动画发声。
- 静音窗口进入混音，边界短渐变避免咔嗒。声音桥可以跨镜头，以叙事作用选择；不强制固定次数。
- 随机材质固定种子；任意时刻重复、乱序、新页面都要产生一致状态。缓存帧以源码、输入、尺寸、帧率指纹隔离。
- 数据形态变化使用稳定数据 id 和同一数值尺度；演示数据显著标明；更改排序、尺度或样本时明确告知观众。

## 检查工具的实际边界

`node assets/style-studio/check.mjs`：检查事件范围、唯一 id、镜头覆盖和代表状态、字幕停留、字幕与事件对齐；输出采样建议。`shot_contract.py` 继续检查镜头连接；两者都不判断审美或声音好坏。

`render.mjs`：同页顺序/逆序、新页面输出 PNG 哈希比较；本机字体/浏览器环境影响跨机器像素结果。此处测试的是新页面，不应称为独立新进程测试。完整跨进程验证另启动浏览器并记录结果。

`score.py`：生成原创合成拟音与字幕，支持 FFmpeg 两遍响度归一化。生成成功并不说明已听音，ASR 能力也未包含在此工具内。旁白项目要另验证逐句发音、词时序和混音可懂度。
